# Agro-Vision AI: Non-Negotiable System Rules

## Machine Learning
1. **Separation of Concerns:** Training code lives exclusively in `/ml`. The Flask app only loads saved artifacts and executes inference.
2. **Data Hygiene:** Fit scalers, encoders, and transformers on the training split only. Never fit on validation or test splits.
3. **Reproducibility & Pipelines:** Use scikit-learn `Pipeline` + `ColumnTransformer` for tabular models, serialized via `joblib`.
4. **Time Series Integrity:** Chronological splits only; never shuffle time-series data.
5. **Auditable Metrics:** Every trained model writes a `metrics.json` recording test metrics, dataset name, split sizes, random seed (42), timestamp, and library versions.
6. **Artifact Format:** Save Keras neural network models with the `.keras` extension.
7. **Baselines:** Always compare model performance against defined baselines (majority class for classification, mean predictor for regression, naive last-value for time series).
8. **Honest Reporting:** NEVER invent or estimate metrics. Only report numbers read directly from `metrics.json` generated by execution.

## Backend & API
1. **Startup Loading:** Load each ML model artifact once at application startup as singletons; never reload per request.
2. **Validation:** Validate all input types and numerical ranges; return JSON error objects with clear messages and correct HTTP status codes.
3. **Upload Security:**
   - Supported extensions: `.jpg`, `.jpeg`, `.png`.
   - Max file size: 5 MB.
   - Use `werkzeug.utils.secure_filename` plus random UUID/hash prefixes for stored filenames.
   - Clean up or isolate uploaded temporary files properly.
4. **Security & Auth:** Hash passwords using Werkzeug security (`generate_password_hash`), enforce CSRF protection on forms, and read secrets from environment variables only.
5. **Advisory Disclaimer:** Treatment advice must always include: *"advisory, consult a local agricultural officer"*. Disease adjustment in cross-module advisor is a clearly labeled, configurable heuristic.

## Workflow & Quality Control
1. **Test-Driven Delivery:** Write unit and route tests for every service and endpoint. Run pytest before declaring any milestone complete.
2. **Ambiguity & Missing Data:** Stop and ask the user if any dataset is missing, corrupted, or synthetic.
3. **Git Commits:** Commit to git with a clear milestone message after every milestone acceptance criteria is met.
